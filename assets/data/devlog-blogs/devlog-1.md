This devlog will be about how I decided to do this C++ project, as well as choosing the libraries and stuff. Well…, this project was born out of my realization of not having a portfolio project that stands out from the others, after all this time of game jamming. Additionally, after I found myself to be more comfortable with doing game tech professionally, I wanted to try and get my hand on the lower level side of making games or game engines.

If you don’t already know, this project is going to be a 3D modeling software. Heavily inspired by Blockbench (I used to make Minecraft mods as a hobby), it will be low-poly and blocky. When I was deciding what to do for a game-engine-esque project, I noticed that Blockbench wasn’t as flexible as I thought, at least to Blender. There are limits to the size of models, as well as grids, and you have to construct the model using just cubes and other generic shapes, can’t really edit the vertices and stuff. Imagine you could turn a cube into a wedge without turning it in fixed rotations. Oh, and voxelization, we need this too. Moreover, as Blockbench was built more for Minecraft, I wanted to make a more generic blocky and low-poly modeling software.

As for the libraries used, I will be using the native Win32 API and OpenGL. The Win32 API is for me to understand more about the lower level side of window creation and actions. Whereas, I chose OpenGL instead of something like Vulkan because it would give me a more smooth curve of learning while making sure that I can get low level knowledge of graphics programming.

After thinking about everything, I wanted to design a structure in order to work on the software step by step, but I have never done anything like this, so I was sort of taking a shot in the dark here. So my plan was just to wing it, probably only make a plan when I have a much better idea what I’m supposed to do.
